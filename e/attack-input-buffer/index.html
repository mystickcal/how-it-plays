Input buffering for attacks

Also called: attack buffer, combo buffer, queued input

A press made during an attack's recovery is saved and fires the moment the attack ends, instead of being thrown away.

←→ or AD move · Space W ↑ or Z jump · X or J attack

Try this: Stand next to the dummy and press X twice quickly. Watch the dropped presses count. A green mark above the player means a press is queued.

What it does

Players press the next attack before the current one finishes. If the game only accepts input when the character is idle, those presses vanish and combat feels sticky. A buffer keeps one press made near the end of recovery and starts the next attack on the first frame it's allowed.

Use it when

Melee combat, combos, fighting games, any move with recovery time.

Watch out

Keep it to one queued press. Queueing every press makes the character keep swinging after the player stopped.

Starting values

A buffer of 100 to 200 ms before recovery ends. Recovery itself of 150 to 300 ms for a light attack.

Prompt for your coding agent

The numbers follow the sliders above. Works with plain canvas, Phaser, Three.js or Godot.

Add an input buffer for attacks.
- Each attack has an active phase and a recovery phase (220 ms).
- If attack is pressed while an attack is running and less than 150 ms of it remain, queue one press.
- When recovery ends and a press is queued, start the next attack on that frame.
- Earlier presses are ignored. Only one press can be queued.
- Show a debug counter of dropped presses.

Acceptance checks:
1. Pressing attack again 75 ms before recovery ends chains into a second attack with no idle frame.
2. Pressing attack at the very start of an attack does not queue anything.
3. Holding the button does not auto-attack.
